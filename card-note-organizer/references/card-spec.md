# 卡片笔记规范

## 卡片标准结构

每张卡片必须包含五个部分，严格使用以下 Markdown 格式：

```markdown
---

## 标题不超十字

### 🏷️ 标签

`#书名/章节名` `#内容标签1` `#内容标签2` `#内容标签3`

### 💬 一句话总结

用一句话（不超过 60 字）概括这条笔记的核心信息。

### 💡 核心洞见

以「一句话总结」为金字塔顶层，下方用 2-5 个并列分论点支撑展开：

- **分论点 1（视角名）**：一句话点明立场，再用 1-2 句展开支撑/对比/例证
- **分论点 2（视角名）**：一句话点明立场，再用 1-2 句展开支撑/对比/例证
- **分论点 3（视角名，可选）**：一句话点明立场，再用 1-2 句展开支撑/对比/例证

> 必要时引用一句关键金句作为支撑（≤1 句）。

### 📎 来源

- **类型**：书籍/文章/网页/对话/灵感/课程/视频/播客/其他
- **出处**：具体来源名称、作者、链接等
- **日期**：YYYY-MM-DD（如果有）
```

## 各字段详细规范

### 标题

- 不超过 10 个汉字
- 用名词短语或短句概括核心主题
- 避免空泛标题，如「读书笔记」「一些想法」
- 标题应便于在 Obsidian、Reminds 或文件中快速检索

### 标签

标签分为两类：**出处标签** 和 **内容标签**。

- 出处标签：1-2 个，用来标识内容来源；默认 1 个，只有来源层级复杂或需要保留两个独立来源线索时才用 2 个。
- 内容标签：2-5 个，由笔记参考的原文和内容总结提炼而成，用来表达主题、概念、方法、行动或领域。
- 总量：通常 3-6 个，复杂笔记最多 7 个；避免为了凑数制造弱标签。
- 层级从宽到窄：从领域大类逐步细化到具体概念。
- 兼顾检索与关联：既要方便日后搜索，也要能串联相关笔记。
- 使用中文标签，简洁准确，2-6 字为宜；出处标签可因书名/章节名适当更长。
- 出处标签可使用 `/` 分割多级层级；例如来自某本书某章节的划线，使用 `#书名/章节名`，来自网页可用 `#网站名/栏目名`。

### 一句话总结

- 严格控制在 60 字以内
- 包含「主题 + 核心观点/发现」，而非仅仅描述主题
- 即使脱离上下文也能独立理解
- 使用肯定句式，避免模糊表达

### 核心洞见

核心洞见必须使用 **金字塔总分结构**：以「一句话总结」作为顶层论点，核心洞见展开 2-5 个并列分论点支撑它。**不再单独写「核心论点」一行**，避免与一句话总结重复。

**结构要求：**

1. **顶层 = 一句话总结**：核心洞见区直接进入分论点，不要再复述或换说法重写一遍总结。
2. **2-5 个并列分论点**：每个分论点以一句话点明立场，再用 1-2 句展开支撑、对比或举例。
   - 分论点之间是并列/对比/递进关系，必须从不同切面共同支撑「一句话总结」。
   - 数量控制在 2-5 个；超过 5 个说明粒度过细，应合并；少于 2 个说明思考不够，应再拆。
3. **每个分论点要有「论」+「据」**：仅有论点而无展开的 bullet，等于没洞见，必须补充原因、机制、例子或对比。
4. **建议在每个分论点前加一个「视角名」**：如「机制」「判别标准」「反例边界」「实践方法」「历史脉络」「适用范围」等，让金字塔的「分」之间逻辑切面清晰。
5. **避免事实复述**：不要照搬原文段落或仅做改写；必须做「抽象 → 抽象后的判断」这一步。
6. **可选的金句引用**：仅当原文存在不可替代的精确表达时，使用 ≤1 句的引用块作为支撑，放在对应分论点之后。

**反面模式（必须避免）：**

- 在核心洞见开头再写一句和「一句话总结」同义的「核心论点」，造成重复。
- 把原文要点变成多级嵌套清单，但没有提炼出统一论点。
- 罗列 6+ 个 bullet 但没有先后逻辑或支撑关系。
- 多个分论点表达同一意思，只是换了说法。

**示例骨架：**

> 一句话总结：平台与企业的核心价值是降低交易成本；不能显著降本的平台不具备长期价值。

```markdown
- **机制**：交易成本理论把企业与平台都解释为「成本套利装置」——内部组织成本低于市场交易成本时，组织或平台才有价值。
- **判别标准**：互联网巨头都可对应一种或几种被压缩的交易成本（淘宝降搜索/信息、支付宝降执行、滴滴降搜索/协调）。
- **反例与边界**：仅把线下流程搬上网而未减少摩擦的项目，无法形成长期价值，往往沦为「在线版的旧流程」。
- **实践方法**：评估新业务时，先写出「省了哪一类交易成本、省了多少」，再决定是否投入。
```

**其他要求：**

- 忠实原意：不歪曲原始笔记的内容。
- 以提炼为主：不大段重复划线原文。
- 区分事实与观点：明确标注哪些是作者观点、哪些是客观事实。
- 必要时在结尾追加「关联笔记」一句，提示与其他卡片的连接。

### 来源

- 类型：从预设分类中选择（书籍/文章/网页/对话/灵感/课程/视频/播客/其他）
- 出处：书名/文章标题/URL/人名等
- 日期：尽可能标注
- 如果用户未提供来源信息，使用「用户提供，未注明出处」并提醒用户补充

## Reminds 写入格式

当输出目标是 Reminds 时，必须遵循以下规则：

1. 保留每个部分的标题，不要省略「标签」「一句话总结」「核心洞见」「来源」标题。
2. 每个部分的标题前固定使用对应 emoji：`### 🏷️ 标签`、`### 💬 一句话总结`、`### 💡 核心洞见`、`### 📎 来源`。
3. 每个部分之间使用 Markdown 分割线 `---` 分隔；转换为 HTML 时使用 `<hr>`。
4. 按 Markdown 层级组织内容；转换为 HTML 时用 `<strong>`、`<em>`、`<blockquote>`、`<mark>` 等区分主次。
5. 标签部分包含 1-2 个出处标签（必要时才用两个）和 2-5 个内容标签；出处标签必要时使用 `/` 分割多级标签，例如 `#芒格之道/2022年每日期刊股东会讲话`。
6. 不要大段复制划线原文；以提炼核心观点为主。

推荐 Reminds HTML 结构：

```html
<h2>标题不超十字</h2>
<hr>
<h3>🏷️ 标签</h3>
<p>#书名/章节名 #内容标签1 #内容标签2 #内容标签3</p>
<hr>
<h3>💬 一句话总结</h3>
<blockquote><mark>一句话总结内容</mark></blockquote>
<hr>
<h3>💡 核心洞见</h3>
<ul>
  <li><strong>分论点 1（视角名）：</strong>一句话点明立场 + 1-2 句支撑/例证</li>
  <li><strong>分论点 2（视角名）：</strong>一句话点明立场 + 1-2 句支撑/例证</li>
  <li><strong>分论点 3（视角名，可选）：</strong>一句话点明立场 + 1-2 句支撑/例证</li>
</ul>
<hr>
<h3>📎 来源</h3>
<ul><li><strong>类型：</strong>书籍划线</li></ul>
```

## 批量处理格式

- 用 `---`（水平线）作为卡片之间的分隔符
- 为每张卡片编号（如 `## 卡片 1`、`## 卡片 2`）
- 在全部卡片末尾生成一个「标签索引」，列出所有标签及其对应的卡片编号

## 质量自检清单

在输出每张卡片前，确认：

- [ ] 标题不超过 10 个汉字，且能准确概括主题
- [ ] 出处标签 1-2 个；默认 1 个，必要时才用 2 个，且可用 `/` 表达来源层级
- [ ] 内容标签 2-5 个，来自原文和内容总结的主题/概念/方法提炼，具备检索价值
- [ ] 一句话总结不超过 60 字，且包含实质信息
- [ ] 核心洞见使用金字塔总分结构：以「一句话总结」为顶层论点，下方 2-5 个并列分论点支撑展开
- [ ] 核心洞见区不再单写「核心论点」一行，避免与一句话总结重复
- [ ] 每个分论点都有视角名 + 论点 + 论据/例证
- [ ] 来源信息完整（至少包含类型和出处）
- [ ] 整体格式美观、易于阅读
